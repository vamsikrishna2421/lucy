# Bugs And Blockers

## Open

- Multilingual privacy scanning is currently heuristic regex preflight. External AI is disabled by default to avoid leakage, but if a user enables it, an unrecognized sensitive phrase could reach Claude before extraction marks it private. Production external processing requires local semantic preflight.
- SQLCipher is not available in Expo Go. Verified startup storage initialization on an Android native development build; future testing must continue using that build path.
- Ollama is retained only as explicit `ollama-dev` development fallback; a physical mobile device cannot generally reach laptop `localhost` without a trusted network route.
- The prototype normal-content Claude path requires an app-visible API key and therefore must not ship as production authentication.
- Anthropic and OpenAI API keys were exposed in conversation and must be rotated before reuse. No key is retained in local project configuration; the Android end-to-end test used local Ollama.
- iPhone native on-device inference remains unverified from this Windows workspace; it requires a physical-device build through macOS/Xcode or a suitable EAS workflow.
- OS-managed background work is opportunistic. LUCY can request registration after user consent, but Android/iOS, not the app, decide the actual execution window and charging/idle conditions.
- Custom splash branding is deferred: the coordinated LUCY splash asset exists, but `expo-splash-screen` integration was removed after launch-handoff instability during native validation. Reintroduce it only in an isolated native pass.
- Windows Android release builds with ExecuTorch fail from the full workspace path because CMake intermediate filenames exceed platform limits; a junction also fails because dependency paths resolve canonically. Current validation uses the physical `C:\LucyNativeBuild` copy.
- Resolved 2026-05-25: Android SDK Platform-Tools already existed and `adb` was added to the user `PATH`; `emu01_master` now builds and runs the app.
